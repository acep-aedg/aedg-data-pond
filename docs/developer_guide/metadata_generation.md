## 📁 Metadata Configuration & Generation Workflow

This is only if you are running the metadata generation on its own. Otherwise the data pipeline was built to run `main.sh`

### Step 1: Verify Dataset Location

Ensure your dataset CSV is merged into the `main` branch of `aedg-data-pond` at:
`data/public/<dataset_folder>/<dataset_file>.csv`

> ⚠️ **Prerequisite:** The CSV **must** be on `main` before creating metadata configs, or remote file validation will fail. This is generated by `aedg-etl-2024` uploaded to `aedg-data-pond` locally. 

### Step 2: Create Dataset Configuration

Copy `config_template.yml` into your dataset's directory in `aedg-data-pond` and populate the fields:

* **Keywords & Topics:** Select keywords from `active_keywords.csv` (add new keywords cautiously). Use existing topics only. Do NOT create new topics.
* **Sources:** Reference the dataset `name` from its corresponding `source.yml` in `aedg-etl-2024` (e.g., `name = acep.monthly_generation`).
* **Contributors:** Reference contributor IDs from `agents.yml`.
* **Fields:** Map every column to `registry fields.csv`. There should be an error message if fields are missing. Check the ETL pipeline's `source.yml` API endpoint if column details are missing and add to `fields.csv`.

## ⚙️ Metadata Generation

### 1. Register Dataset

Add your dataset name to `generate_metadata.yml` in `aedg-metadata`. Unlisted datasets will be skipped during generation.

### 2. Set Local ETL Path

In `./src/generate_metadata.sh`, temporarily set `SOURCE_DIR_PATH` to your local `aedg-etl-2024` repository path.

> ⚠️ **Note:** Do not commit this local path change to Git.

### 3. Run Build Scripts

```bash
# Generate JSON metadata
./src/generate_metadata.sh

# Generate Markdown documentation
./src/generate_markdown.sh

```

### 4. Submit Changes

Commit your updated YAML and generated metadata files to a feature branch, push to remote, and open a Pull Request.
